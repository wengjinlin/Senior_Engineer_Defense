## 1 生态扫描总览（26 种 agent CLI）

**扫描范围**：Multica 平台官方支持的 agent CLI 清单 + 公开生态中活跃的编码 agent CLI（npm/GitHub 活跃度、近 3 个月发版情况）。

**信息来源**：Multica 平台文档口径、各 CLI 官方仓库 README/Release、内网试用实测。

**扫描维度**：维护活跃度 / 多会话能力（并行、会话隔离）/ 工具链生态（MCP、skills、hooks 扩展点）/ 公司内网可自托管性。

**初筛清单**（按结论分组；Multica 支持的 26 种 CLI 中与本项目评估相关的代表性条目如下）：

| CLI | 维护活跃度 | 多会话能力 | 工具链生态 | 可自托管 | 初筛结论 |
|---|---|---|---|---|---|
| Claude Code | 高（周级发版） | 子代理 + hooks + 会话机制完整 | MCP / skills / PreToolUse 钩子最完整 | ✅ 本机 CLI | **进入深度评估** |
| Codex CLI | 高 | 会话能力中等 | MCP 支持 | ✅ | 备选 |
| Gemini CLI | 高 | 单会话为主 | MCP 支持 | ✅ | 备选 |
| opencode | 中高 | 多会话 | 插件生态发展中 | ✅ | 备选（后作为多 CLI 适配验证对象） |
| Qwen Code | 中 | 单会话 | MCP 支持 | ✅ | 备选（同上） |
| Trae | 中 | 单会话 | IDE 绑定较强 | 部分 | 备选（同上） |
| Aider / Cline / Roo Code / Continue 等 IDE-编辑器系 | 中 | 编辑器内单会话 | 各自生态 | ✅/部分 | 仅编辑器场景，不适合流水线编排 |
| Cursor / Windsurf / Copilot 类 | 高 | IDE 绑定 | 闭源云服务为主 | ❌ 数据出公司 | **落选（合规）** |
| Crush / Goose / OpenCode 系轻量终端 agent | 中 | 单会话 | 早期 | ✅ | 观察名单 |
| 其余（自托管单代理流、实验型 CLI） | 低—中 | 单会话 | 弱 | ✅ | 落选（生态不成熟） |

> 扫描总结论：生态处于爆发期但分层明显——**只有头部 CLI 具备"可被编排器拉起、可注入约束、可扩展工具"的三要素**；其余或绑定 IDE、或依赖云端、或生态过早。选型应"执行引擎选头部、编排与治理自研"。

## 2 候选框架深度评估

### 2.1 Claude Code（执行引擎）——✓ 采纳

评估要点：子代理机制（Explore/Plan/Apply 分工）；**PreToolUse 钩子**可在工具调用前程序化注入 block 决策（写入拦截的物理基础）；skills 机制可整包注入业务能力；会话上下文与 CLAUDE.md 开工必读机制天然承载"项目宪法"。本机 CLI 形态、无云端强制依赖。
结论：作为执行引擎唯一满足"约束可注入 + 行为可拦截 + 能力可扩展"三项硬要求的候选。

### 2.2 OpenSpec（工件规范）——✓ 采纳

评估要点：proposal→specs→design→tasks 工件链顺序（`ordering: strict` 可强制跳序即 block）；change 目录约定天然形成审计轨迹；`tdd_enforcement: strict` 提供测试门禁配置位。
结论：以最小成本把"文档驱动"从口号变成机器可校验的顺序铁律，直接针对 AI"先码后文、WHAT/HOW 混淆"两大缺陷。

### 2.3 superpowers（工程方法论）——✓ 采纳

评估要点：TDD skill（红-绿-重构 5 步）、writing-plans skill（2-5 分钟粒度原子任务）——把工程纪律封装为 skill，agent 按纪律执行而非靠自觉。
结论：与 OpenSpec 工件链互补：工件链管"做什么的顺序"，superpowers 管"怎么做的纪律"。

### 2.4 Multica（编排平台）——✓ 采纳

评估要点：Go + PostgreSQL 自托管、本机 Runtime 守护进程拉起 agent CLI（无需中心算力池）；可拉起 26 种 agent CLI；issue/chat 交互面与 GitLab 集成（webhook、建 MR）；密钥 env 网页注入通道。
结论：私有化部署可行、数据不出公司，"平台层不自研"的关键复用件。

### 2.5 落选对比项

| 落选项 | 落选理由 |
|---|---|
| Copilot 类补全深化 | 不改开发模式，收益天花板低（工具级 vs 流程级） |
| 自研多 Agent 平台 | 开发量以年计；IT 无专职平台团队 |
| gstack 单代理流 | 单会话串行、9 关审查全量跑（实测 ~15 分钟/次）；无多角色接力与并行能力——但其浏览器基座与 QA 方法论被收编进 aicoding-browser-qa 技能 |
| 云端 Agent 平台（Manus 类） | 数据出公司，信息安全合规一票否决 |

## 3 组合式选型结论

**Multica（底座）+ Claude Code（执行引擎）+ OpenSpec（工件规范）+ superpowers（工程方法论）**——全部开源自托管，自研面压缩到"编排机制 + 治理层 + 业务技能"薄层（约可复用 70%+ 成熟组件）。

该结论与《软件需求说明书》§4 方案比选表（A 补全深化 / B 自研平台 / C 组合式）及答辩报告 A1 节口径一致：组合式是"半年内建成落地"的唯一可行路线——后续 2026.05-11 六系统落地验证了这一判断。
