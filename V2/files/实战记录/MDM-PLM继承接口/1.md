界面设计
菜单栏：
视图审批管理
变体视图




    接口逻辑：    MDM逻辑
    1.一次维护一个工厂物料的多个变体。
    2.选择值的变体值维护，无论工厂+物料+变体代码是否已存在，变体值按照先新增变体值，再重复值去除的方式
执行。
3.创建人是按照接口传参的 XT 字段，PLM的默认是800001PLM。

    4.变体视图保存后，审核物料，且返回视图审核的报错。

    MDM判断逻辑：
    "物料工厂变体视图维护接口
├── 第一层判断：物料+工厂 是否存在于【MDM_VIEW_ALL视图审批管理】
│ ├── 否 → 报错：失败，工厂物料不存在 → 结束
│ └── 是 → 进入第二层判断
│
├── 第二层判断：N_SAP是否已导入SAP（值为1）
│ ├── 否 → 报错：失败，工厂物料未导入 → 结束
│ └── 是 → 进入第三层判断
│
├── 第三层判断：工厂+变体代码 是否存在于【MDM_BTCGL变体管理】
│ ├── 否 → 报错：失败，变体代码不存在 → 结束
│ └── 是 → 进入第四层判断
│
├── 第四层判断：物料+工厂+变体代码 是否存在于【MDM_VIEW_VARIANT变体视图】
│ ├── 否 → 执行操作：新建变体视图（物料+变体代码+需求管控+状态新增）→ 进入第五层判断
│ └── 是 → 执行操作：更改变体视图（按照物料+变体代码 更新需求管控+状态）→ 进入第五层判断
│
├── 第五层判断：变体代码维护属性是否为输入值
│ ├── 是 → 成功，工厂物料变体视图维护成功→ 结束
│ └── 否 → 进入第六层判断
│
├── 第六层判断：传参中是否存在MDM_VIEW_MX结构数据
│ ├── 否 → 报错：失败，变体值缺失 。回滚第四层的 物料+变体代码+需求管控+状态 的维护 → 结束
│ └── 是 → 进入第六层判断
│
└── 第七层判断：工厂+变体代码下的全部变体值是否在对应工厂+变体代码的变体明细【MDM_BTCGL_MX表】中存在
├── 否 → 【MDM_BTCGL_MX表】中插入缺失的变体值和插入变体视图的变体值（变体视图值重复项自动去除）→
成功，工厂物料变体视图维护成功→ 结束
└── 是 → 插入变体视图的变体值（变体视图值重复项自动去除）→ 成功，工厂物料变体视图维护成功→ 结束"
